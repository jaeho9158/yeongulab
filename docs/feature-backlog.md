# 기능 백로그 — 브레인스토밍·평가 기록

오푸스5가 브레인스토밍하고 페이블 5.1이 평가해 구현 계획으로 옮긴다. 라운드마다 아래에 누적한다.
채택된 항목만 구현 대상이다. 기각 항목은 **왜 기각했는지**를 남겨 다음 라운드에서 같은 제안이 다시 올라오지 않게 한다.

## 상태 기호

- `[ ]` 채택, 미착수
- `[~]` 진행 중
- `[x]` 완료(커밋 해시)
- `[-]` 기각 (사유 필수)
- `[?]` 운영자 판단 필요 — 물어볼 때까지 대기

## A. 채택 — 즉시 (근거가 확인됐고 리스크가 없다)

### A1. `/tools` 색인을 실제 도구 앵커로 링크 `[ ]` S

`app/tools/page.tsx:86`이 24개 도구 전부를 `/guide/{stage}#tools` 한 곳으로 보낸다.
그런데 `lib/stageToolMeta.ts`의 `TOOL_IDS`와 `StageTools`의 해시 딥링크는 **이미 동작한다**.
색인 페이지만 그걸 안 쓰고, 대신 66~72줄에서 사용자에게 한계를 사과하고 있다.

- href를 `/guide/{stage.slug}#tool-{TOOL_IDS[title]}`로 교체
- 사과 문단 삭제 → 안내 한 줄로 교체
- `app/showcase/page.tsx`의 `/guide/submission#tools` → `#tool-showcase`
- 테스트: `TOOL_IDS`에 없는 제목이 오면 타입 에러로 이미 막힌다. 추가 테스트 불필요.

**평가**: 라운드 1 최고 가성비. 이미 만든 기능이 연결만 안 돼 있는 상태다.

### A2. sitemap `lastModified`를 문서별 날짜로 `[ ]` S

`app/sitemap.ts:8`의 `const lastModified = new Date()`를 40여 URL이 공유한다.

색인 할당량이 빠듯한 지금 특히 손해다.

- 글: `new Date(article.updated)`
- 사례: `new Date(showcase.published)`
- 단계·정적 페이지: 빌드 시각 유지 (실제로 코드와 함께 바뀐다)
- 테스트: 자료실 URL의 lastModified가 서로 다른 값을 갖는지

### A3. Article JSON-LD에 `image` 추가 `[ ]` S

원칙과 충돌하지 않는다. 기사 리치결과 자격 조건이다.

- `image`에 `{SITE_URL}/articles/{slug}/opengraph-image`
- 사례 JSON-LD도 같이 (showcase OG 있음)
- 주석의 "지어내지 않는다" 문장은 유지하되 "OG 라우트가 실재하므로 image는 예외"를 덧붙인다

### A4. 자료실 상세에 광고 슬롯 1개 `[ ]` S

검색 유입이 가장 크게 떨어질 31편 롱폼의 수익 면적이 0이다.

## B. 채택 — 검증 후 (설계 판단이 하나씩 붙는다)

### B1. 통계 계산기에 대응표본 t·카이제곱 `[ ]` M

`docs/articles-content-plan.md` §5-A가 통계 글에 검정 선택표를 넣고 계산기로 링크하기로 했는데,
`lib/stats.ts`는 Welch t·상관·회귀 셋뿐이다. 표가 안내한 칸을 계산기가 못 받는다.

- 대응표본 t: 차이의 평균/표준편차 → 기존 `tTestTwoTailedP` 재사용, df = n-1
- 카이제곱 독립성: 2×2부터 r×c까지. p값에 불완전 감마 함수 필요 — `chiSquareP` 추가
- **ANOVA는 이번 라운드 제외.** F분포 p값(불완전 베타)이 추가 수치해석 부담이고,
  중고생 연구에서 3집단 이상은 대응 t·카이제곱보다 드물다. 다음 라운드 재검토.
- `lib/statsVerdict.ts`에 각 검정의 해석 문구 추가 — 기존 "유의하다≠크다" 톤 유지
- 테스트: R/scipy로 검산한 고정값 케이스 최소 6개

### B2. 차트 오차막대 `[ ]` M

`content/articles/14-figure-first.mdx`가 "오차막대를 읽어라"라고 가르치는데
`SimpleChart`로는 그릴 수 없다. 가르치는 것과 주는 도구가 어긋난다.

- `lib/chartGeometry.ts`의 `parsePairs`를 3열(라벨, 값, ±)로 확장 — **3열은 선택**
- bar·line에만. 산점도·원형은 무의미하므로 UI에서 열 자체를 숨긴다
- 축 범위 계산에 오차 상단/하단을 포함해야 잘리지 않는다 (이게 실제 함정)

### B3. 마감일 `.ics` 내보내기 `[ ]` S

`31-finding-calls`의 결론이 "공고를 늦게 봐서 못 낸다"인데
마감이 이 브라우저 localStorage에만 남으면 그 문제를 그대로 재현한다.
서버 없이 알림을 줄 수 있는 유일한 정직한 경로다.

- `lib/ics.ts` 순수 함수 + `PlanExport`의 Blob 다운로드 패턴 재사용
- VALARM 7일 전 1개. 여러 개 넣지 않는다(캘린더 앱마다 처리가 다르다)
- **CRLF 줄바꿈과 75옥텟 폴딩**을 지켜야 한다. 한글 SUMMARY에서 UTF-8 바이트 경계를 쪼개면 깨진다 — 여기가 유일한 난점
- 테스트: 한글 제목 폴딩, 특수문자 이스케이프(쉼표·세미콜론·역슬래시), DTSTART 형식

### B4. 레퍼런스 BibTeX·RIS 내보내기 `[ ]` S

`lib/citations.ts`가 APA·IEEE 문자열만 만든다.
`PriorResearchSearch`로 모은 논문이 사이트 밖으로 못 나가면 도구 체인이 거기서 끊긴다.

- `Reference` 타입 필드가 그대로 매핑된다
- BibTeX 키 생성 규칙(저자성+연도+제목첫단어)과 한글 저자 처리 주의
- 중괄호·앰퍼샌드·퍼센트 이스케이프

## D. 기각

### D1. DOI → Crossref 자동 채우기 `[-]`

**기각 사유**: 제안 자체는 좋으나 지금이 아니다. `app/api/search-papers/route.ts`가 이미 있어
기술적으로는 라우트 하나지만, 학생이 붙여넣는 DOI가 서버 로그에 남는다.
`/privacy`의 "서버로 전송되지 않습니다" 문장과 부딪힌다 — 논문 검색은 이미 예외로 명시돼 있지만
인용 도구는 "내가 쓰는 참고문헌 목록"이라 성격이 다르다.
**재상정 조건**: `/privacy`에 예외 범위를 정확히 적고, 운영자가 승인한 뒤.

### D2. 클라이언트에서 Crossref 직접 호출 `[-]`

(D1의 우회로로 떠오를 수 있어 미리 적는다)
**기각 사유**: CORS는 통과하지만 학생 IP가 Crossref에 직접 노출되고 polite pool 이메일을 클라이언트에 박아야 한다.

### D3. 홈 `WebSite` + `SearchAction` 구조화 데이터 `[-]` (부분)

**기각 사유**: `SearchAction`은 실제 검색 URL이 있어야 한다. C1 전에는 거짓말이다.
`Organization`은 `/about`에 이미 운영자 실명이 있어 새로 만드는 실익이 작다. **C1과 함께 재검토.**

### D4. 목록 페이지 `ItemList` JSON-LD `[-]`

**기각 사유**: 구글이 `ItemList`로 리치결과를 주는 건 특정 유형(레시피, 영화 등)뿐이다.
일반 문서 목록에는 효과가 사실상 없다. 코드만 늘어난다.

### D5. 서비스워커 오프라인 캐시 `[-]`

**기각 사유**: 애드센스 심사 중 광고 스크립트 캐시는 정책 위반 소지. 매니페스트(B8)까지만.

## E. 운영자 판단 대기 `[?]`

물어볼 때까지 진행하지 않는다.

1. **헤더에 "자료실" 추가** — `SiteNav.tsx` 주석이 375px에서 가용폭을 이미 다 썼다고 **실측**으로 적어 놨다.
   4번째 항목을 넣으면 nav-scroll이 받아주지만 좁은 화면에서 스크롤이 생긴다.
   "예시"를 빼고 "자료실"을 넣을지, 스크롤을 감수할지가 운영자 판단이다.
2. **홈에 사례 섹션** — 사례 6편이 홈에서 링크되지 않는다. 홈 길이를 늘릴지.
3. **`NEXT_PUBLIC_ADSENSE_CLIENT_ID`** — 미설정이면 광고 0개를 위해 전 페이지가 스크립트를 받는다.
4. **"지니어스 클럽" 팀명 복원** — ARIA 사례에서 익명화하며 제거했다.
5. **익명 집계 통계 롤아웃** — `docs/anonymous-stats-design.md`가 "애드센스 재검토 결과 뒤"로 순서를 정해뒀다.

## F. 제약 위반 확인 (재제안 금지)

### M6. 사례 절 구조가 제각각이고 절반이 막다른 길 `[ ]` M

6편 공통 절은 `## 다음 사람에게` 하나뿐이다.
`## 함께 볼 것`은 3편에만 있어 **절반이 나가는 링크 없는 막다른 길**이다.
한계 절은 이름이 셋이고 `01-trem2`는 아예 없다. 첫 절도 둘로 갈린다.

- 고정 골격: 질문 / 방법 / 결과 / 막혔던 지점 / 스스로 밝힌 한계 / 다음 사람에게 / 함께 볼 것
- 서사형 2편은 중간만 자유롭게 두고 앞뒤를 맞춘다
- `## 함께 볼 것`은 6편 전부 필수
