### 고정 골격 (확정)

```
## 어떤 질문에서 시작했나        ← 6편 필수, 이름 고정(부제 허용)
(중간)
## 스스로 밝힌 한계              ← 6편 필수, 이름 고정
## 다음 사람에게                 ← 6편 필수 (이미 충족)
## 함께 볼 것                    ← 6편 필수, 항상 파일 마지막 절
```

절차형 3편(lyso·eeg·adr)은 중간도 고정한다:
`## 어떻게 확인했나` → `## 무엇이 나왔나` → `## 가장 막혔던 지점`.

**서사형 2편(`01-trem2`, `05-focused-ultrasound`)의 예외 처리**

이 둘은 시간순 서사(1차→2차→3차)가 내용 자체다. 중간 절을 `어떻게 확인했나`로 뭉개면
"질문이 다음 질문을 낳는다"는 이 사례들의 유일한 교훈이 사라진다.
→ **앞(첫 절)과 뒤(한계·다음 사람에게·함께 볼 것)만 맞추고 중간은 그대로 둔다.**
백로그가 적은 그대로이며 실측 후에도 이 판단이 유지된다.

`04-aria`는 서사형과 절차형의 중간이다(`가장 중요한 지점 — 데이터를 못 구했다`가 이 편의 축).
→ **중간 절 이름을 지키고 앞뒤만 맞춘다.** 서사형과 같은 취급.

```markdown
투고 폼(`ResearchShowcaseForm`)으로 받은 원고를 운영자가 검토해 올리는 구조라,
검토 시 적용할 기준을 여기에 고정한다.

## 원칙

**직접 식별자를 지우는 것으로는 부족하다.** 실명·학교명·팀명은 당연히 뺀다.
문제는 **조합으로 좁혀지는 정보**다. 명부가 존재하는 소수 집단에 속했다는 사실 하나가
다른 세부와 결합하면 원본 보고서와 작성자를 특정한다.

## 지우는 것 — 경로 정보

교육적으로 필요 없는 **어떻게 그 자리에 갔는가**는 일반화한다.

| 유형 | 예 | 고쳐 쓰는 법 |
| --- | --- | --- |
| 프로그램 참여 경위 | "여름방학에 대학에서 여는 고교생 대상 약학 프로그램에 참여" | "약학 분야 강연에서 … 들었다" |
| 시약·장비 조달 경로 | "대학 실험실에 있는 지인에게 EDC를 빌려" | "다른 경로로 EDC를 확보해" |
| 대회·학술제 이름 | "○○과학전람회 출품작" | "교내 학술제 보고서" 또는 생략 |
| 지도·자문 관계 | "○○대 □□교수 자문" | 생략 |
| 지역·시기의 조합 | "2025년 2학기 △△지역 연합 동아리" | "한 학기 동안 동아리에서" |

## 지우지 않는 것 — 방법과 숫자

**통계값·측정 조건·시약 농도·기기 설정·표본 수·검정 결과는 그대로 둔다.**
그게 사례가 존재하는 이유다. 재식별 위험을 이유로 방법을 뭉개면 사례가 아니라 감상문이 된다.

출처(`sources` frontmatter)도 지우지 않는다 — 기관명·데이터셋명은 공개 자료의 신원이지
작성자의 신원이 아니다.

## 검토 절차

원고를 받으면 순서대로 확인한다.

1. 직접 식별자(이름·학교·팀·아이디·이메일)가 남아 있는가
2. 위 표의 다섯 유형에 해당하는 문장이 있는가
3. 남은 정보만으로 검색해 원본을 찾을 수 있는가 —
   특히 **명부가 공개된 프로그램 + 정확한 데이터 출처 + 정확한 기간**의 조합
4. 지운 뒤에도 방법과 숫자가 그대로 남아 있는가(3을 이유로 2를 넘어서지 않았는가)
```

```ts
function readShowcaseFile(filename: string): Showcase {
  const raw = fs.readFileSync(path.join(SHOWCASE_DIR, filename), "utf-8");
  const { data, content } = matter(raw);

  // 출처 없는 사례는 올리지 않는다. 빌드에서 막지 않으면 투고가 쌓이는 만큼
  // 빈 필드가 늘어난다(S6과 같은 가드).
  if (!Array.isArray(data.sources) || data.sources.length === 0) {
    throw new Error(
      `${filename}: showcase frontmatter에 sources가 필요합니다(최소 1건). ` +
        `기준은 docs/showcase-anonymization.md의 "지우지 않는 것" 참고.`,
    );
  }
  if (
    data.sources.some((s: unknown) => typeof s !== "string" || !s.trim())
  ) {
    throw new Error(
      `${filename}: sources 항목은 비어 있지 않은 문자열이어야 합니다.`,
    );
  }

  return {
    slug: data.slug,
    title: data.title,
    summary: data.summary,
    schoolLevel: data.schoolLevel,
    byline: data.byline,
    published: data.published,
    relatedStage: data.relatedStage,
    sources: data.sources,
    content,
  };
}
```

### 코드 — `lib/guide.ts` (`:44` `getStageBySlug` 다음)

```ts
export type WeekRange = { min: number; max: number };

/**
 * `estimatedWeeks`는 `"4~8주 (가변)"` `"1~2주 + 심사 대기"`처럼 꼬리가 붙는
 * 자유 문자열이다. 앞머리의 `n~m주` 또는 `n주`만 읽고 나머지는 버린다.
 * 형식을 벗어나면 null을 돌려주고 테스트가 그걸 실패로 잡는다 —
 * 조용히 0으로 세면 합계가 틀린 채로 통과한다.
 */
export function parseWeekRange(value: string): WeekRange | null {
  const m = /^\s*(\d+)\s*(?:~\s*(\d+)\s*)?주/.exec(value);
  if (!m) return null;
  const min = Number(m[1]);
  const max = m[2] === undefined ? min : Number(m[2]);
  if (max < min) return null;
  return { min, max };
}

/** 단계별 `estimatedWeeks`의 합. 하나라도 파싱 실패면 null. */
export function totalWeekRange(
  stages: { estimatedWeeks: string }[],
): WeekRange | null {
  let min = 0;
  let max = 0;
  for (const s of stages) {
    const r = parseWeekRange(s.estimatedWeeks);
    if (!r) return null;
    min += r.min;
    max += r.max;
  }
  return { min, max };
}
```

```ts
function checksKey(slug: string) {
  return `research-guide:reflection-checks:${slug}`;
}

/**
 * 저장된 체크 상태를 질문 수에 맞춰 정규화한다.
 * 질문이 늘거나 줄어도(T4로 05·06이 바뀐다) 옛 배열이 그대로 살아 있으면
 * "다 찼다"가 거짓이 되므로, 길이를 맞추고 넘치는 값은 버린다.
 */
function normalizeChecks(raw: unknown, count: number): boolean[] {
  const arr = Array.isArray(raw) ? raw : [];
  return Array.from({ length: count }, (_, i) => arr[i] === true);
}
```
