### T2 · question-vs-researchable

- **제목** "궁금하다"와 "탐구 가능하다"는 다르다 — 질문을 검증 가능한 형태로
- **검색어** 탐구 주제 정하는 법 / 연구질문 만들기 / 탐구 가능한 질문 / 탐구 질문 예시
- **relatedStage** topic · **featured** false
- **한 줄** 관심사에서 출발한 질문이 왜 그대로는 연구가 안 되는지, 어떤 변환을 거치면 되는지를 실제 문장 10쌍으로.
- **H2**
  1. 궁금한 질문이 연구가 안 되는 세 가지 형태 (답이 이미 있다 / 잴 수 없다 / 너무 크다)
  2. 변환 규칙 1 — "왜"를 "무엇이 무엇에"로
  3. 변환 규칙 2 — 형용사를 측정값으로
  4. 변환 규칙 3 — 대상을 "내가 닿을 수 있는 집단"으로
  5. 변환 전후 10쌍 (표: 원래 질문 / 왜 안 되나 / 바꾼 질문)
  6. 바꾼 질문을 스스로 판별하는 점검표 5항목
- **도구** `내 연구질문, 조사형일까 탐구형일까` (H2-1 끝), `연구주제 아이디어 뽑기` (H2-5 끝)
- **교차링크** 가이드 1단계 "'조사'와 '탐구'는 다르다", topic-ideas "좁히는 방식은 셋 중 하나다"
- **중복 점검** 가이드 1단계가 조사/탐구 구분을 이미 다룬다 → 여기서는 구분을 반복하지 않고 **변환 규칙**에 집중
- **[사례 슬롯]** H2-5 표의 마지막 쌍을 운영자 실제 질문 변환으로 교체

### T3 · from-curriculum

- **제목** 교과 단원에서 탐구로 넘어가는 네 가지 경로
- **검색어** 교과 연계 탐구 주제 / 생명과학 탐구 주제 / 화학 탐구 주제 / 물리 탐구 주제 / 세특 탐구 주제
- **relatedStage** topic · **featured** true (topic-ideas와 교체 — 검색 수요가 이쪽이 더 크다)
- **한 줄** 단원 하나를 대상·변수·척도·맥락 넷 중 하나만 바꿔 탐구로 만드는 방법을 6개 과목에서 각각 보여준다.
- **H2**
  1. 단원은 답이 정해진 실험이다 — 그래서 하나만 바꾼다
  2. 네 가지 경로 (대상 바꾸기 / 변수 바꾸기 / 척도 바꾸기 / 맥락 바꾸기) — 각 경로마다 한 문장 정의 + 예시 1
  3. 생명과학 I — 단원 3개 × 경로 1개씩 (효소 / 항상성 / 생태)
  4. 화학 II — 단원 3개 (반응속도 / 평형 / 산염기)
  5. 물리 I·II — 단원 3개 (역학 / 파동 / 전자기)
  6. 심리·사회문화 — 단원 3개 (기억 / 사회화 / 통계자료)
  7. 정보 — 단원 3개 (알고리즘 효율 / 데이터 / 네트워크)
  8. 경로를 골랐다면 — 다음 세 가지 확인
- **분량 예외** 절이 많아 4,500자 이상 허용. H2-3~7은 각 400자 내외, 표 형식(단원 / 바꾼 것 / 탐구 질문 / 조심할 점).
- **도구** `연구주제 아이디어 뽑기` (H2-2), `변수 정의표 만들기` (H2-8)
- **교차링크** topic-ideas(분야별 절과 1:1 대응), right-sized-topic(H2-8)
- **중복 점검** topic-ideas는 "관심사 → 질문"이고 이 글은 "단원 → 질문"이다. **예시 주제가 topic-ideas 48개와 하나도 겹치지 않아야 한다** — 집필 전 48개를 목록으로 뽑아 대조.
- **[사례 슬롯]** 운영자 연구 분야의 절에 실제 경로 1개

### T4 · from-a-paper

- **제목** 논문 한 편에서 탐구 주제 세 개 뽑는 법
- **검색어** 논문에서 탐구 주제 찾기 / 선행연구 후속 연구 / 논문 Discussion 읽는 법 / future work
- **relatedStage** topic · **featured** false
- **한 줄** 논문의 Discussion 마지막 문단은 저자가 "다음에 할 일"을 적는 곳이다. 거기서 학생이 할 수 있는 크기의 주제를 뽑는 절차.
- **H2**
  1. 저자는 논문 끝에 다음 연구를 적어둔다 (limitation·future work의 위치와 관용 표현 6개)
  2. 세 가지 뽑기 — 한계를 조건으로 (limitation → 조건 바꿔 재검) / 미검증 가설을 질문으로 / 다른 집단으로
  3. 실제 논문 한 편으로 해보기 (오픈액세스 논문 1편 실명 인용, DOI 포함, 세 주제 도출)
  4. 뽑은 주제가 "고등학생 크기"인지 확인
  5. 원 논문을 어떻게 인용하나 — 아이디어 출처 밝히기
- **도구** `선행연구 검색해보기` (H2-1), `내 레퍼런스 목록` (H2-5)
- **교차링크** reading-english-papers(H2-1), figure-first, right-sized-topic(H2-4), research-ethics "표절: 출처의 문제다"(H2-5)
- **중복 점검** reading-english-papers "읽는 순서"가 Discussion을 언급한다 → 여기서는 순서가 아니라 **마지막 문단의 해부**만
- **사실 검증** H2-3의 논문은 실제 존재하는 CC-BY 논문이어야 하고, 인용 문장은 실제 문장이어야 한다. 집필자가 DOI를 열어 확인.

### T5 · why-topics-go-stale

- **제목** 탐구 주제가 진부해지는 세 가지 이유
- **검색어** 흔한 탐구 주제 / 식상한 탐구 주제 / 탐구 주제 차별화 / 세특 주제 겹침
- **relatedStage** topic · **featured** false
- **한 줄** "식물과 음악", "커피와 집중력"이 왜 매년 나오는지와, 같은 재료로도 진부함을 벗어나는 방법.
- **H2**
  1. 진부한 주제 목록이 아니라 진부해지는 **구조**가 있다
  2. 이유 1 — 변수가 검색 첫 페이지에서 왔다
  3. 이유 2 — 결과를 이미 알고 시작한다
  4. 이유 3 — 척도가 "느낌"이다
  5. 같은 재료를 살리는 법 — 조건 하나를 극단으로 / 척도를 바꾸기 / 반대 결과를 찾기
  6. 내 주제가 진부한지 30초 판별
- **도구** `연구주제 아이디어 뽑기` (H2-5)
- **교차링크** 가이드 1단계 "흔히 하는 실수: 결과가 이미 정해진 실험"(H2-3에서 링크로 대체, 재설명 금지), question-vs-researchable(H2-4)
- **중복 점검** 가이드 1단계 "결과가 이미 정해진 실험" 절 → **재서술 금지**, 링크만

### T6 · right-sized-topic

- **제목** 끝낼 수 있는 크기인가 — 고등학생 연구의 범위 판별법
- **검색어** 탐구 범위 정하기 / 연구 주제 좁히기 / 탐구 기간 계획 / 한 학기 탐구
- **relatedStage** topic · **featured** false
- **한 줄** 주제가 좋은데 끝을 못 내는 연구가 가장 많다. 표본·기간·장비·분석 넷으로 크기를 재는 법.
- **H2**
  1. 못 끝낸 연구의 공통점 — 크기를 재지 않았다
  2. 네 가지 자 (표본 / 기간 / 장비 / 분석)
  3. 자로 재보기 — 큰 주제 3개를 작게 자르는 실제 과정
  4. 작게 잘랐는데도 연구가 되는 이유
  5. 주제 크기 점검표 (8항목, 예/아니오)
- **도구** `표본 크기 계산기` (H2-2 표본), `마감일 트래커` (H2-2 기간)
- **교차링크** 가이드 1단계 "시간 계획: 한 학기를 기준으로", "실현 가능성·안전·멘토", small-sample(H2-2)
- **중복 점검** 가이드 1단계의 시간 계획 절과 겹치지 않도록 — 여기서는 **주제를 자르는 행위**, 가이드는 일정표

### T7 · replication-is-research

- **제목** 선행연구가 이미 다 했을 때 — 재현 연구의 가치
- **검색어** 재현 연구 / 선행연구 이미 있음 / 반복 실험 연구 / 재현성
- **relatedStage** topic · **featured** false
- **한 줄** "이미 논문이 있어요"는 포기 이유가 아니다. 재현이 왜 연구인지, 어떻게 설계해야 재현이 되는지.
- **H2**
  1. "이미 있다"에서 멈추는 학생, 거기서 시작하는 연구자
  2. 재현이 연구인 이유 — 재현 위기 한 문단 (링크로 근거)
  3. 세 종류 — 직접 재현 / 조건 재현 / 개념 재현
  4. 재현 연구 설계할 때 반드시 같게 할 것, 달라도 되는 것
  5. 결과가 원 논문과 다를 때 쓰는 법
  6. 재현 연구를 보고서에 어떻게 자리매김하나
- **도구** `선행연구 검색해보기` (H2-1), `연구윤리 · 재현가능성 체크리스트` (H2-4)
- **교차링크** 가이드 5단계 "재현 가능과 반복 가능은 다르다"(H2-2), negative-results(H2-5), borrowing-methods(H2-4)
- **중복 점검** 가이드 5단계의 재현/반복 구분 → 링크만

### T8 · public-data-topics

- **제목** 공공데이터로 탐구 설계하기 — 실험 없이 하는 사회 연구
- **검색어** 공공데이터 탐구 / 통계 자료 탐구 주제 / KOSIS 활용 / 사회문화 탐구
- **relatedStage** topic · **featured** false
- **한 줄** 설문도 실험도 없이, 이미 공개된 통계로 할 수 있는 연구. 어디서 받고, 어떤 질문이 가능하고, 무엇을 조심하나.
- **H2**
  1. 데이터를 만들지 않아도 연구다
  2. 어디서 받나 — 국내 4곳 (KOSIS·공공데이터포털·교육통계·기상자료개방포털), 각각 무엇이 있고 어떤 형식인지
  3. 공공데이터로 가능한 질문 형태 — 추세 / 지역 비교 / 두 지표 관계
  4. 반드시 조심할 것 — 생태학적 오류 한 문단, 집계 단위, 정의 변경
  5. 실제로 해보기 — 데이터 1개 받아 질문 1개 답하는 과정 (표·그래프 포함)
  6. 출처 표기와 이용 약관
- **도구** `간이 차트 그리기` (H2-5), `인용 형식 만들어보기` (H2-6)
- **교차링크** statistics "상관은 인과가 아니다"(H2-4), question-vs-researchable
- **사실 검증** H2-2의 사이트 4곳 URL과 제공 형식을 집필일에 확인

### S1 · start-with-reviews

- **제목** 리뷰 논문부터 읽어야 하는 이유
- **검색어** 리뷰 논문 / 선행연구 어디서부터 / 종설 논문 / 문헌 고찰 시작
- **relatedStage** prior-research · **featured** true
- **한 줄** 선행연구 첫 검색에서 원저 논문을 열면 길을 잃는다. 리뷰 한 편이 논문 30편의 지도가 되는 이유와 찾는 법.
- **H2**
  1. 첫 검색 결과 20개를 다 열어보면 생기는 일
  2. 리뷰 논문은 무엇이고 어떻게 알아보나 (제목 표지어 · 초록 구조 · 참고문헌 수)
  3. 리뷰의 어느 부분을 읽나 — 서론 마지막·표·결론만
  4. 리뷰에서 원저로 내려가기
  5. 리뷰가 없는 주제라면
  6. 리뷰 한 편으로 만드는 첫 종합표
- **도구** `선행연구 검색해보기` (H2-2 — 검색어에 review 붙이기), `내 레퍼런스 목록` (H2-6)
- **교차링크** 가이드 2단계 "읽은 논문을 한 장의 종합표로 모으기"(H2-6, 재설명 금지), citation-chaining(H2-4)
- **중복 점검** 가이드 2단계 "어디서 검색하는가"가 데이터베이스를 나열한다 → 여기서는 나열하지 않고 **리뷰 식별**만

### S2 · riss-kci

- **제목** RISS·KCI에서 한국어 논문 찾기
- **검색어** RISS 사용법 / KCI 논문 검색 / 한국어 논문 찾기 / 국내 논문 검색
- **relatedStage** prior-research · **featured** false
- **한 줄** 영어 논문 전에 한국어로 먼저. 두 사이트가 무엇이 다르고, 고등학생이 무료로 어디까지 볼 수 있나.
- **H2**
  1. 한국어로 먼저 찾아야 하는 이유 (용어 확인 · 국내 맥락)
  2. RISS — 무엇이 있고, 검색창에 무엇을 넣나, 원문 보기 조건
  3. KCI — RISS와 다른 점, 등재지 표시가 뜻하는 것
  4. 검색어 만들기 — 한국어 학술 용어는 일상어와 다르다 (예시 8쌍)
  5. 원문이 안 열릴 때 — 학교 도서관·공공도서관 상호대차·저자 요청
  6. 찾은 논문을 인용 형식으로
- **도구** `선행연구 검색해보기` (H2-4), `인용 형식 만들어보기` (H2-6)
- **교차링크** free-full-text(H2-5), start-with-reviews
- **사실 검증** RISS·KCI 화면 구성·무료 범위를 집필일에 확인. 스크린샷은 넣지 않는다(UI 변경 시 낡음) — 문장으로만.

### S3 · pubmed-mesh

- **제목** PubMed 5분 사용법 — MeSH로 검색 정확도 올리기
- **검색어** PubMed 사용법 / MeSH 검색 / PubMed 검색 팁 / 의학 논문 검색
- **relatedStage** prior-research · **featured** false
- **한 줄** 생명과학·보건 주제라면 PubMed다. 키워드 검색과 MeSH 검색이 왜 다른 결과를 내는지, 5분 안에 쓸 수 있는 만큼만.
- **H2**
  1. Google Scholar 대신 PubMed를 쓰는 경우
  2. 그냥 검색하면 생기는 일 — 동의어 문제
  3. MeSH란 무엇인가 (한 문단, 정의보다 **왜 있는지**)
  4. 5분 절차 — MeSH 찾기 → 검색식 → 필터(리뷰·연도·무료 전문)
  5. 검색식 읽고 쓰기 — AND/OR/괄호 예시 3개
  6. 결과 화면에서 볼 것 — "Free PMC article" 표시
- **도구** `선행연구 검색해보기` (H2-1 — 이 도구가 PubMed를 포함하는지 집필 시 확인해 문장 조정)
- **교차링크** free-full-text(H2-6), reading-english-papers
- **사실 검증** PubMed 필터 이름·MeSH 브라우저 URL을 집필일에 확인

### S4 · free-full-text

- **제목** 논문 전문에 무료로 접근하는 합법적 경로
- **검색어** 논문 무료로 보는 법 / 논문 전문 열람 / 오픈액세스 / 유료 논문 무료
- **relatedStage** prior-research · **featured** false
- **한 줄** 초록만 보이고 전문은 유료일 때. 불법 사이트 없이 되는 여섯 가지 경로, 되는 순서대로.
- **H2**
  1. 왜 유료인가 — 한 문단 (길게 쓰지 않는다)
  2. 경로 1 — 오픈액세스 버전 찾기 (Unpaywall류 확장 · PMC · DOAJ)
  3. 경로 2 — 저자 원고(preprint·accepted manuscript) (arXiv·bioRxiv·기관 리포지토리)
  4. 경로 3 — 저자에게 직접 요청 (메일 템플릿 1개)
  5. 경로 4 — 도서관 (공공도서관 학술DB · 대학 도서관 개방)
  6. 하지 말아야 할 것 — 해적 사이트를 **이름 없이** 한 문단으로. 왜 안 되는지(법·보안)
  7. 전문 확보 점검 순서표
- **교차링크** research-ethics(H2-6), riss-kci, pubmed-mesh
- **중복 점검** riss-kci H2-5와 겹침 → riss-kci 쪽은 이 글로 링크하고 짧게
- **사실 검증** 확장 프로그램·서비스 이름과 존속 여부를 집필일에 확인

### S5 · citation-chaining

- **제목** 인용된 논문 따라가기 — 한 편에서 스무 편으로
- **검색어** 인용 따라가기 / 참고문헌 활용 / 선행연구 확장 / cited by
- **relatedStage** prior-research · **featured** false
- **한 줄** 좋은 논문 한 편을 찾았다면 검색은 그만해도 된다. 뒤로(참고문헌)와 앞으로(피인용) 따라가는 법.
- **H2**
  1. 검색보다 따라가기가 빠른 이유
  2. 뒤로 — 참고문헌 목록에서 고르는 기준 (본문에서 여러 번 인용된 것 · 제목에 내 변수가 있는 것)
  3. 앞으로 — "인용된 횟수" 클릭 (Scholar·Semantic Scholar·KCI 피인용)
  4. 두 방향을 종합표에 쌓기
  5. 멈추는 기준 — 같은 논문이 반복해서 나올 때
  6. 함정 — 인용 수가 질을 뜻하지 않는다
- **도구** `내 레퍼런스 목록` (H2-4)
- **교차링크** start-with-reviews(H2-1), 가이드 2단계 "출처의 질을 판단하는 법"(H2-6, 재설명 금지)

### S7 · figure-first

- **제목** Figure만 보고 논문의 주장 파악하기
- **검색어** 논문 그림 읽는 법 / Figure 해석 / 논문 빨리 읽기 / 그래프 읽기
- **relatedStage** prior-research · **featured** true
- **한 줄** 논문의 주장은 Figure 1~3에 다 있다. 캡션·축·오차막대·별표를 순서대로 읽어 본문 없이 결론을 재구성하는 훈련.
- **H2**
  1. 저자는 그림을 먼저 만들고 글을 쓴다
  2. 읽는 순서 — 캡션 첫 문장 → 축 라벨 → 범례 → 데이터 → 별표·오차막대
  3. 그림 유형별 한 문장 결론 — 막대 / 선 / 산점도 / 상자 (각 유형에 "이 그림이 말할 수 있는 것과 없는 것")
  4. 실제 논문 Figure 1개로 해보기 (CC-BY 논문의 그림을 **묘사**로. 이미지 재게재 안 함)
  5. 그림과 초록이 안 맞을 때 — 그게 발견이다
  6. 내 그림을 그릴 때 거꾸로 적용하기
- **도구** `간이 차트 그리기` (H2-6), `그림·표 캡션 도우미` (H2-6)
- **교차링크** reading-english-papers "통계 기호 읽기"(H2-2 별표 부분, 재설명 금지), statistics "그래프에서 하지 말아야 할 것"(H2-6)
- **중복 점검** statistics의 그래프 절은 "내 그래프에서 하지 말 것" → 여기는 **남의 그래프 읽기**
- **[사례 슬롯]** H2-4를 운영자 연구의 그림으로 교체 가능

### S8 · borrowing-methods

- **제목** Methods를 읽어야 하는 이유 — 남의 방법을 빌려오는 기술
- **검색어** 논문 방법 참고 / 실험 방법 찾기 / 연구 방법 인용 / Methods 읽기
- **relatedStage** methodology · **featured** false
- **한 줄** 학생 연구에서 방법을 새로 만들 필요는 없다. 검증된 방법을 찾아 조건만 바꿔 쓰는 것이 정석이고, 그게 표절이 아닌 이유.
- **H2**
  1. 방법을 빌리는 것은 연구의 기본이다
  2. Methods 절에서 찾을 것 — 재료·장비·절차·측정·분석 다섯 칸
  3. 빌릴 때 반드시 바꾸는 것과 절대 바꾸지 않는 것
  4. 학생 환경으로 낮추기 — 장비 대체표 (예시 6개)
  5. 출처 표기 — "~의 방법을 따랐다(수정함)"의 정확한 형식
  6. 방법을 빌렸다면 결과도 비교하라
- **도구** `변수 정의표 만들기` (H2-2), `인용 형식 만들어보기` (H2-5)
- **교차링크** replication-is-research(H2-6), research-ethics "표절: 출처의 문제다"(H2-5), 가이드 3단계 "도구·자료 명세"
- **[사례 슬롯]** H2-4 대체표에 운영자 실제 대체 사례

### S9 · scholar-alerts

- **제목** Google Scholar 알림으로 후속 논문 놓치지 않기
- **검색어** 구글 스칼라 알림 / 논문 알림 설정 / 새 논문 추적 / Scholar alert
- **relatedStage** prior-research · **featured** false
- **한 줄** 연구는 몇 달 걸리고 그 사이 새 논문이 나온다. 5분 설정으로 내 주제의 새 논문을 메일로 받는 법과, 받은 다음 무엇을 하나.
- **H2**
  1. 선행연구는 한 번 하고 끝이 아니다
  2. 알림 설정 절차 (검색 → 알림 만들기 → 검색식 다듬기)
  3. 알림이 너무 많이 올 때 — 검색식 좁히기 3가지
  4. 저자 팔로우 — 핵심 저자 1~2명
  5. 온 논문을 어떻게 처리하나 — 30초 판별 → 종합표 추가 또는 버림
  6. 제출 직전 마지막 확인
- **분량 예외** 주제가 좁아 2,500자 허용. 대신 H2-5를 두껍게.
- **도구** `내 레퍼런스 목록` (H2-5)
- **교차링크** 가이드 2단계 "논문 한 편을 10분 만에 판별하는 순서"(H2-5, 재설명 금지), citation-chaining
- **사실 검증** Scholar 알림 UI 문구를 집필일에 확인

### M1 · question-to-test

- **제목** 연구질문 → 가설 → 검증 방법, 연결이 끊기는 지점
- **검색어** 가설 세우기 / 연구질문과 가설 / 검증 방법 설계 / 탐구 가설 예시
- **relatedStage** methodology · **featured** true
- **한 줄** 질문은 좋은데 가설이 질문과 다른 말을 하고, 검증 방법은 가설을 확인 못 하는 보고서가 절반이다. 세 고리가 끊기는 여섯 지점.
- **H2**
  1. 세 문장이 한 줄로 이어져야 한다 (질문 / 가설 / 검증 — 예시 1세트)
  2. 끊김 1 — 질문의 변수와 가설의 변수가 다르다
  3. 끊김 2 — 가설이 방향 없이 "관계가 있다"
  4. 끊김 3 — 검증이 가설의 반대를 허용하지 않는다
  5. 끊김 4 — 측정값이 변수를 대표하지 않는다
  6. 끊김 5·6 — 비교 대상 부재 / 분석 계획 부재
  7. 끊긴 곳 찾는 표 (내 세 문장을 써넣는 빈 표 + 채운 예시 2개)
- **도구** `목적 진술 만들어보기` (H2-1), `변수 정의표 만들기` (H2-2), `내 연구질문에 맞는 설계 유형 찾기` (H2-6)
- **교차링크** 가이드 3단계 "분석 계획과 가설: 데이터를 모으기 전에 적는다"(H2-6, 재설명 금지), question-vs-researchable, control-group-mistakes(H2-6)
- **[사례 슬롯]** H2-7 채운 예시 하나를 운영자 실제 세 문장으로

### M2 · control-group-mistakes

- **제목** 대조군 설계에서 학생들이 가장 많이 틀리는 지점
- **검색어** 대조군 설정 / 대조군 실험군 차이 / 통제 변인 / 대조군 없는 실험
- **relatedStage** methodology · **featured** false
- **한 줄** 대조군을 "아무것도 안 한 집단"으로 알고 있으면 이미 틀렸다. 실제 보고서에서 반복되는 다섯 가지 오류와 고친 설계.
- **H2**
  1. 대조군은 "없음"이 아니라 "그것만 빼고 같음"이다
  2. 오류 1 — 대조군이 처치 외에 다른 것도 다르다
  3. 오류 2 — 대조군이 없다 (전후 비교만)
  4. 오류 3 — 대조군이 하나인데 처치 조건이 넷
  5. 오류 4 — 대조군 표본이 실험군보다 훨씬 작다
  6. 오류 5 — 사람 대상인데 무엇을 받는지 안다
  7. 고친 설계 다섯 개 나란히 (전/후 표)
- **도구** `변수 정의표 만들기` (H2-2), `랜덤 표본 추첨기` (H2-6)
- **교차링크** 가이드 3단계 "변수 정의"(H2-1), question-to-test, small-sample(H2-5)
- **중복 점검** 가이드 3단계 "흔히 하는 실수 두 가지" 확인 후 겹치는 오류는 링크로

### M3 · small-sample

- **제목** 표본이 부족할 때 할 수 있는 것과 없는 것
- **검색어** 표본 수 부족 / 설문 인원 적을 때 / 표본 크기 작은 연구 / 소표본 통계
- **relatedStage** data-collection · **featured** false
- **한 줄** 반 친구 25명이 전부일 때. 그 수로 말할 수 있는 것, 말하면 안 되는 것, 그리고 수를 늘리지 않고 설계를 바꾸는 방법.
- **H2**
  1. 표본이 작다는 것은 무엇이 작다는 뜻인가 (검정력 한 문단, 수식 없이)
  2. 할 수 없는 것 — 작은 차이 검출 / 일반화 / 하위집단 비교
  3. 할 수 있는 것 — 큰 효과 검출 / 기술통계 / 사례 서술 / 파일럿
  4. 설계로 보완하기 — 반복 측정 / 짝지은 설계 / 효과 크기 보고
  5. 보고서에 어떻게 쓰나 — 한계 절 문장 예시 3개
  6. "몇 명이면 되나"에 답하는 법

### W2 · negative-results

- **제목** 실험이 실패했을 때 쓰는 법 — 음성 결과도 결과다
- **검색어** 실험 실패 보고서 / 가설 기각 / 결과 안 나왔을 때 / 음성 결과
- **relatedStage** writing · **featured** true
- **한 줄** 가설이 틀렸거나 차이가 안 나왔을 때 보고서를 포기하는 학생이 많다. 그 결과를 정직하게, 그리고 가치 있게 쓰는 법.
- **H2**
  1. "안 나왔다"는 세 가지 다른 상황이다 (가설 반대 / 차이 없음 / 측정 실패)
  2. 상황별로 무엇을 말할 수 있나
  3. 하지 말아야 할 것 — 데이터 더 모으기·조건 바꿔 다시·p값 낮은 것만 골라내기 (각각 왜 안 되는지)
  4. 결과 절 쓰기 — 있는 그대로, 해석 없이
  5. 논의 절 쓰기 — 왜 그랬을 가능성이 있는지 네 단락 구조 적용
  6. 제목과 초록을 음성 결과에 맞게 고치기
  7. 음성 결과 보고서 실제 예시 (가상, 결과·논의 각 한 단락)
- **도구** `IMRaD 구조 점검` (H2-4), `간이 통계 계산기` (H2-2)
- **교차링크** research-ethics "데이터를 다룰 때 넘지 말아야 할 선"(H2-3, 재설명 금지), 가이드 5단계 "논의는 네 단락이면 된다"(H2-5), limitations, replication-is-research, statistics "p값이 말해주는 것"

### W3 · limitations

- **제목** 논문의 한계를 솔직하게 쓰는 게 왜 유리한가
- **검색어** 연구의 한계 쓰는 법 / 한계점 예시 / 논문 limitation / 탐구 한계점
- **relatedStage** writing · **featured** false
- **한 줄** 한계 절을 짧게 얼버무리면 심사위원이 대신 써준다 — 더 세게. 한계를 먼저 밝히는 것이 방어인 이유와 쓰는 구조.
- **H2**
  1. 심사위원은 한계를 이미 알고 있다
  2. 한계 절이 하는 일 — 결론의 범위를 긋는 것
  3. 쓰는 구조 — 한계 / 영향 / 대응 또는 미대응 이유 (세 문장 세트)
  4. 자주 나오는 한계 6종과 각각의 정직한 문장
  5. 한계로 쓰면 안 되는 것 — "시간이 부족했다"

- **분량 예외** 2,500자 허용

- **relatedStage** submission · **featured** false

  1. 왜 이 글은 일정표가 아닌가 (두 문단. 낡은 일정의 해악)
  2. 공고가 나는 곳 — 주최 유형별 (교육청·대학·학회·재단·기업) 각각 어디를 보나
  3. 공고 주기 — 유형별 대략의 시기(월 단위, 특정 연도 아님)
  4. 공고를 읽는 법 — 자격·분량·제출물·심사 기준을 표로 뽑기
  5. 30분 결정법 — 내 연구 단계와 공고의 요구 대조
  6. 지원 준비물 공통 목록 (요약문·지도교사 확인·동의서·발표자료)
  7. 놓치지 않는 법 — 알림·캘린더·공고 모음 사이트
- **도구** `투고처 후보 모음` (H2-2), `마감일 트래커` (H2-7), `발표 시간 재보기` (H2-6)
- **교차링크** 가이드 6단계 "투고처 고르기"(H2-5), presentation
- **사실 검증** H2-2·H2-7의 사이트는 **기관 공식 도메인만**. 특정 대회명·연도·날짜는 쓰지 않는다. 이것이 이 글의 존재 조건이다.

- `lib/ogFontChars.ts` (신규): 테스트의 `hangulInSources()` + 글 제목 + 단계 제목 수집 로직을 `collectOgChars(): string`으로 옮긴다. 항상 포함하는 안전 집합을 더한다: ASCII 32~126, `·—–…‘’“”「」`, 한글 자모 없음(완성형만). 테스트는 이 함수를 import해 쓴다(중복 제거).
- `scripts/og-font-subset.ts` (신규, Node 24 네이티브 타입 스트립으로 `node scripts/og-font-subset.ts` 실행):
  1. `assets/fonts/src/NotoSansKR-{Bold,Medium}.ttf` 존재 확인. 없으면 **다운로드하지 않고** 안내만 출력하고 exit 1: `https://github.com/google/fonts/tree/main/ofl/notosanskr` 에서 받아 그 경로에 두라고. (원본 ~5MB × 2를 저장소에 넣지 않는다 → `.gitignore`에 `assets/fonts/src/`)
  2. `collectOgChars()`를 스크래치 텍스트 파일에 쓴다.
  3. `python -m fontTools.subset <src> --text-file=<tmp> --output-file=assets/fonts/NotoSansKR-<W>.ttf --layout-features='' --no-hinting --desubroutinize` 를 `child_process.execFileSync`로 실행. fonttools 4.61이 로컬에 있음을 확인했다(2026-09-05).
  4. 결과 크기를 출력. 50KB를 넘으면 경고(글자가 예상보다 많이 늘었다는 신호).
- `package.json` scripts에 `"og-font": "node scripts/og-font-subset.ts"`.
- 라운드 절차: 글 추가 → `npm test` 실패 확인 → `npm run og-font` → `npm test` 통과 → 커밋에 폰트 포함.
