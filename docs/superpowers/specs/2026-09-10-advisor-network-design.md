# 자문위원 네트워크 설계

작성일 2026-09-10 · 상태: 설계 승인 대기 · 구현 착수 전

## 1. 무엇을 만드는가

연구할Lab에 **학·석·박사, 교수, 연구원, 기업 전문가가 자문위원으로 등록하고,
중·고등학생이 연구에 대해 질문할 수 있는 페이지**를 만든다.

운영 주체는 **지니어스 클럽**이고, 자문위원은 **전원 무급**이다.
경쟁 서비스의 기능은 최대한 가져오되 **비용을 0으로 내리는 것**이 설계 목표다.

### 근거 자료

기능 선택은 전부 사전 조사 산출물인 **「연구 멘토링 기능 지도」**
(35개 서비스 · 48개 기능 · 7개 축)에 근거한다.
https://claude.ai/code/artifact/b29a9a8d-3bb4-46fa-aac6-4ac241ba2927

## 2. 설계를 결정한 두 가지 발견

기능 지도에서 두 문장이 이 설계 전체를 결정했다.

**(1) 상호작용 형식이 안전 비용을 결정한다.**
> "비동기 공개 Q&A — 접촉이 공개·기록으로 남아 안전 리스크가 가장 낮다" (B축)

성인이 미성년자와 1:1로 만나는 순간 D축(미성년자 안전) 9개 기능이 전부 필요해진다.
신원조회·범죄경력 조회·세션 녹화·보호자 계정·참관·카메라 규칙·사후 점검.
이건 무료 서비스가 감당할 수 있는 비용이 아니다.

그런데 **1:1을 화상이 아니라 사이트 내 텍스트 스레드로 구현하면** 대부분이 자동으로 해결된다.

| D축 기능 | 텍스트 스레드에서 해결되는 방식 | 추가 비용 |
|---|---|---|
| 세션 전량 녹화 | 전문이 DB에 그대로 남는다 | 0 |
| 보호자 참관 | 보호자에게 스레드 열람 권한 부여 | 0 |
| 보호자 전용 대화창 | 보호자 열람은 읽기 전용으로 분리 | 0 |
| 카메라 상시 온 규칙 | 대상 자체가 없음 | — |
| 플랫폼 내 소통 강제 | 연락처 패턴 자동 탐지 + 약관 | 낮음 |
| 금품 제공 금지 | 약관 1개 조항 | 0 |
| 신고 버튼 | 스레드마다 신고 버튼 | 낮음 |
| 보호자 상위 계정 | 미성년자 가입 시 보호자 메일 동의 | 중간 |
| 매칭 사후 점검 | 운영자 대시보드에서 스레드 열람 | 낮음 |

화상 인프라 비용도 0이다. **이것이 B축 1:1을 무료로 내리는 유일한 방법이다.**

**(2) 무급 공급자의 동력은 돈이 아니다.**
> "무보수 멘토를 3.8만 명 모은 ADPList가 실제로 쓰는 것들. 돈이 아니라 인정이 동력이다" (G축)

E축(결제) 10개 기능을 전부 버리는 대신, 그 자리를 G축(리텐션)으로 메운다.
배지·응답률·주간 큐레이션이 유급 보수를 대체하는 장치다.

여기에 B축의 저커밋먼트 모델을 결합한다.
> "연 4통 · 총 10시간. 커밋먼트를 극단적으로 낮춰 무보수 자원봉사자 1,000명+를 확보" (Letters to a Pre-Scientist)

자문위원이 **자기 부담을 스스로 정하게 한다** — "월 답변 가능 건수" 설정.
"시간을 얼마나 뺏길지 모른다"는 불안이 무급 공급의 최대 이탈 요인이기 때문이다.

## 3.5 이 설계가 닫는 격차

기능 지도의 마지막 대조표(「연구할Lab 현재 위치 — 보유 8 · 미보유 12」)는
미보유 12개가 **전부 사람 축에 몰려 있다**고 지적한다.
이 기능은 그 12개를 직접 겨냥한다.

| 미보유 항목 (지도 기준) | 이 설계에서 | 단계 |
|---|---|---|
| 멘토 프로필 · 검색 | 자문위원 디렉토리 + 4축 정렬 + 상태 필터 | 1 |
| 기관 이메일 인증 | 매직링크 + 2단계 배지 | 1 |
| 비동기 공개 Q&A | 공개 질문·답변 | 2 |
| 1:1 세션 (음성·화상) | **텍스트 스레드로 대체** — 비용 0, 기록 자동 | 3 |
| 보호자 계정 · 동의 절차 | 미성년자 1:1 시 보호자 메일 동의 + 열람 | 3 |
| 녹화 · 신고 · 안전 정책 | 전문 기록(자동) + 신고 버튼 + 약관 | 3 |
| 배지 · 랭킹 등 리텐션 | 배지 · 응답률 · 주간 큐레이션 (랭킹 제외) | 4 |
| 멘토 경력 증명 발급 | **채택 안 함** — 학생 임의단체 발급 증명의 신뢰도 문제 |  |
| 교실 단위 라이브 Q&A | 보류 — 학교 제휴 채널이 아직 없다 |  |
| 결제 · 정산 · 수수료 | **의도적 미채택** — 무료가 설계 목표 |  |
| 학교 · 기관 B2G 채널 | 미래 항목 (§E 스폰서 부담) |  |
| 결과물 발표 무대 | 범위 밖 — 지니어스 클럽 학술지·발표회 계획 |  |

12개 중 **7개를 닫고, 3개는 의도적으로 버리며, 2개는 채널이 생긴 뒤로 미룬다.**

그리고 보유 8개는 그대로 활용된다. 특히 **탐구 주제 아이디어 생성**은
질문 작성 화면과 연결하고, **탐구보고서 열람 DB**는 기존 `content/showcase/`가
이미 그 역할을 하고 있어 새로 만들지 않는다.

## 4. 자문위원 프로필 스키마

물어볼Lab · 리로스쿨 · ADPList의 필드 합집합에서, 무급·비대면·미성년자 대상에 필요한 것만 남겼다.

```
[인증 — 비공개, 화면에 절대 노출하지 않음]
  institutionEmail   기관 이메일. 매직링크 인증 전용
  verifiedAt         인증 시각
  documentUrl        재학/학위 증빙 (선택, 운영자만 열람)

[정체 — 공개]
  displayName        표시명 (실명 또는 "김○○ 연구원")
  institution        소속 기관
  department         학과
  position           학부생 | 석사과정 | 박사과정 | 박사후연구원 | 교수 | 기업 연구원 | 기업 실무자
  labName            소속 랩 (선택)
  fields[]           연구분야 태그
  bio                한 줄 소개
  answerableTopics[] 답변 가능 분야

[활동 — 자문위원이 직접 제어]
  monthlyQuota       월 답변 가능 건수 (기본 3)
  status             받는 중 | 쉬는 중
  acceptsPrivate     1:1 스레드 수락 여부

[신뢰 — 시스템 산출, 수정 불가]
  badge              이메일 인증 | 서류 확인
  answerCount        누적 답변 수
  responseRate       응답률
  medianResponseHours 평균 응답 시간
  joinedAt           합류일

[동의 — 가입 시 필수]
  agreedGuidelines       자문 가이드라인
  agreedNoGifts          금품 제공 금지
  agreedNoOffPlatform    개인 연락처 교환 금지
  agreedUnpaid           무급 확인
```

### 배지를 2단계로 나누는 이유

기능 지도의 경고를 그대로 반영한 것이다.

> "한국 @*.ac.kr은 학부생도 갖는다 — 학위과정 증빙이 따로 필요하다"

`ac.kr` 도메인 인증만으로 "박사과정"을 보증할 수 없다.
그래서 자동으로 붙는 `이메일 인증` 배지와, 운영자가 서류를 확인해야 붙는
`서류 확인` 배지를 분리한다. 학생에게는 두 배지의 차이를 명시적으로 설명한다.

**기관 이메일은 어떤 화면에도 노출되지 않는다.** 표시되는 것은
`한국대 · 화학과 · 박사과정 · ✓인증` 형태의 배지뿐이다.
연락 수단이 아니라 **커리어 인증 수단**이기 때문이다.

## 5. 데이터 흐름

### 자문위원 등록
```
지원 폼 작성 → 기관 이메일로 매직링크 발송 → 클릭 시 인증 완료
  → 상태: 심사 대기 → 회장 승인 → 공개
  → (선택) 증빙 서류 제출 → 회장 확인 → '서류 확인' 배지
```

### 공개 Q&A
```
학생이 질문 작성 (분야 태그 선택)
  → 해당 분야 자문위원 중 '받는 중' + 쿼터 여유 있는 사람에게 알림
  → 자문위원이 답변 작성
  → 공개 게시 · 검색 노출 · 자문위원 answerCount 증가
```

### 1:1 텍스트 스레드
```
학생이 특정 자문위원에게 1:1 요청 (acceptsPrivate=true인 경우만)
  → 미성년자면 보호자 이메일 입력 필수
  → 보호자에게 동의 요청 메일 발송 (열람 링크 포함)
  → 보호자 동의 후 스레드 개설
  → 전문 기록 · 보호자/운영자 읽기 전용 열람 가능
  → 연락처 패턴 감지 시 경고 + 운영자 플래그
```

## 6. 단계 구분

각 단계는 독립적으로 출시 가능하다.

**1단계 — 자문위원 레지스트리**
프로필 스키마 · 기관 이메일 인증 · 배지 · 디렉토리 페이지 · 정렬/필터 · 승인 흐름.
자문위원이 0명이면 이후 전부가 빈 껍데기이므로, 공급 확보가 먼저다.

**2단계 — 공개 Q&A**
질문 작성 · 답변 · 분야 매칭 알림 · 쿼터 · 응답률 산출 · 검색 노출.

**3단계 — 1:1 텍스트 스레드**
보호자 동의 흐름 · 스레드 · 열람 권한 · 신고 · 연락처 패턴 탐지.
D축 안전장치가 전부 여기 붙는다.

**4단계 — 리텐션**
배지 · 주간 큐레이션 · 자문위원 활동 요약.

## 7. 법적 · 정책적 제약

설계에 이미 반영했으며, 구현 시 위반해서는 안 되는 항목이다.

- **학원법** — 자문위원 전원 무급이므로 유상 교습에 해당하지 않는다. 유급 전환 시
  전면 재검토 필요. 지도 인용: "재학 중인 대학원생이면 개인과외 신고 면제,
  휴학·졸업생·포닥은 신고 의무, 교원은 전면 금지"
- **개인정보보호법** — 만 14세 미만은 법정대리인 동의 필수. 3단계 보호자 동의 흐름이 이를 충족한다.
- **초·중등교육법 (2026.7.29 시행)** — 학생부 상업적 이용 금지. 학생부 관련 기능·추천서를
  일절 만들지 않는다.
- **개인정보처리방침 전면 개정** — 현재 방침은 "이름·이메일·전화번호 등을 서버에 수집하지
  않습니다"라고 공개적으로 약속하고 있다(app/privacy/page.tsx). 이 기능은 그 약속과
  정면으로 충돌하므로, **구현 착수 전에 방침을 반드시 먼저 개정해야 한다.**
- **AdSense** — 사용자 생성 콘텐츠가 생긴다. 심사 중 상태에 영향을 줄 수 있으므로
  2단계 출시 시점을 AdSense 승인 이후로 잡는다.

## 8. 미해결 항목

- **Supabase 프로젝트 슬롯이 없다.** 무료 플랜은 조직당 2개 제한이며,
  1주일 미사용 시 자동 일시정지된다. 새 조직 생성 또는 기존 프로젝트 정리가
  구현 착수의 선행 조건이다.
- **자문위원이 아직 0명이다.** 코드보다 이쪽이 진짜 병목이다.
  1단계 착수와 병행해 모집 제안서(학회 소개 · 역할 · 시간 부담 · CV 표기 예시 ·
  답변 가이드라인)를 작성해 학과·랩 메일링으로 배포해야 한다.
- **알림 발송 수단 미정.** 매직링크와 보호자 동의 메일에 발송 인프라가 필요하다.
  Supabase 내장 메일은 발송량 제한이 있어 1단계에서 실측 후 결정한다.
