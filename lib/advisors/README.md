# lib/advisors — 자문위원 네트워크 도메인 로직

**이 디렉터리의 코드는 아직 어디에서도 쓰이지 않는다.** 페이지도, DB도, 폼도 없다.
자문위원 네트워크 기능을 실제로 켜기 전에 도메인 로직만 미리 구현해 둔 것이다.

## 왜 이것만 먼저 있나

기능 전체를 켜려면 두 가지가 선행돼야 한다.

1. **개인정보처리방침 개정** — 현재 방침은 "이름·이메일·전화번호 등을 서버에
   수집하지 않습니다"라고 공개적으로 약속하고 있다(`app/privacy/page.tsx`).
   자문위원 기능은 이 약속과 충돌하므로, 기능을 켜기 전에 방침을 먼저 고쳐야 한다.
2. **Supabase 프로젝트** — 무료 플랜 슬롯이 아직 확보되지 않았다.

그래서 **수집이 물리적으로 불가능한 부분만** 먼저 구현했다. 이 디렉터리에는
DB 클라이언트도, 네트워크 호출도, 환경변수 접근도 없다. 전부 순수 함수라
입력을 받아 값을 돌려줄 뿐이고, 테스트로 완전히 검증된다.

## 파일

| 파일 | 책임 |
|---|---|
| `types.ts` | 도메인 타입. DB 스키마와 UI가 공유하는 단일 출처 |
| `validate.ts` | 프로필 입력 검증 |
| `badges.ts` | 기관 이메일 판정과 2단계 배지 산출 |
| `ranking.ts` | 정렬 4축·응답률·응답 시간 표기·추천 점수 |
| `labs.ts` | 소속 랩으로 자문위원 묶기 |
| `matching.ts` | 질문 분야 기반 자문위원 매칭 |
| `quota.ts` | 한국 시각 기준 월 답변 쿼터 |
| `safety.ts` | 개인 연락처·외부 채널 유도 탐지 |
| `consent.ts` | 보호자 동의 토큰과 유효 기간 |
| `achievements.ts` | 활동 배지 |
| `spotlight.ts` | 이번 주 자문위원 큐레이션 |

## 지켜야 할 경계

**이 디렉터리의 파일은 Supabase를 import하지 않는다.** DB를 아는 파일은 앞으로
추가될 `queries.ts`와 `actions.ts`뿐이다. 이 경계 덕분에 도메인 로직 전체가
DB 없이 테스트되고, 지금처럼 기능을 켜지 않은 상태에서도 검증이 끝난다.
